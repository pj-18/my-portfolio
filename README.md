# PJ: a feature presentation

The personal site of Praveen Kumar (PJ): code by day, cinema by night, frames in between.

It's one page staged like a night at the cinema:

| Reel | What's there |
| --- | --- |
| Countdown | A 3·2·1 film leader. It plays once per visit; tap, Enter or Esc skips it. |
| Title card | The headline, plus a hanging "Admit one" ticket you can grab and swing. |
| 01 · The film diary | Live from Letterboxd: stats, a ratings histogram that filters the diary, ticket-stub posters, full reviews in a bottom sheet, the one-liners ticker, a critic's pick, and your lists as cinema programmes. |
| 02 · The soundtrack | Your top 10 artists and songs from Apple Music (via Last.fm) for the last 30 days, 12 months or all time: the artists as a gig-poster line-up with a spotlight, the songs as a two-sided record on a turntable that plays 30-second previews. |
| 03 · The darkroom | Your photos on a film strip that "develop" as they scroll in, a contact-sheet view, and a viewfinder lightbox with the camera settings read from EXIF. |
| 04 · The day job | About, a Playwright-style test run of your career, and the stack. |
| Fin. | Contact, rolling credits and a post-credits "spin the reel" film picker. |

Off the reel, `/tours/` lists trips, and each trip gets a page per day (`/tours/<slug>/`) with a map that follows along. See [Tours](#tours-trips-day-by-day).

It is built mobile first with [Astro](https://astro.build) and a little vanilla TypeScript, with no UI framework.
It respects `prefers-reduced-motion` and works without JavaScript (minus the toys).

## Run it

Needs Node 22.23 or newer (24 recommended, see `.nvmrc`).

```sh
npm install
npm run dev        # http://localhost:4321
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server. Fetches Letterboxd and Last.fm only if there is no data yet. |
| `npm run films` | Pulls the latest Letterboxd diary into `src/data/letterboxd.json`. |
| `npm run music` | Pulls your Last.fm charts into `src/data/music.json` (see [Music](#music-apple-music-via-lastfm)). |
| `npm run music:sample` | Rebuilds the made-up preview data the soundtrack shows in dev before yours exists. |
| `npm run up-next` | Fetches Letterboxd posters for newly booked shows (see [Up next](#up-next-booked-shows)). |
| `npm run build` | Pulls Letterboxd and Last.fm (and posters for new bookings), then builds the static site into `dist/`. |
| `npm run build:offline` | Builds from the saved data without touching the network. |
| `npm run preview` | Serves `dist/` locally. |
| `npm run check` | Type-checks everything. |
| `npm run photos:placeholders` | Repaints the placeholder photos (never overwrites existing files). |
| `npm run tours:roads` | Looks up the driving route for each trip day that has none yet (`-- --all` redoes every day). |

## Make it yours

### Words: `src/site.config.ts`

Everything personal is in this file: name, role, email, links, the about paragraph, the test names the terminal "runs" and the stack ticker.

- In `about`, `[word|green]`, `[word|amber]` and `[word|red]` highlight a keyword, and `*words*` sets them in italic serif.
- `hideFromQuotes` takes film titles whose reviews you'd rather keep out of the one-liners ticker. Reviews are otherwise shown exactly as written on Letterboxd.

### Photos: `src/photos/`

Drop JPEG, PNG, WebP or AVIF files in `src/photos/`. On build, each one is:

- resized into responsive WebP versions, with all metadata stripped from the published files;
- read for camera, lens, focal length, aperture, shutter speed, ISO and date (EXIF). **GPS is never read.**
- given a title, caption and place from IPTC (what Lightroom calls Title, Caption and Location) if you set them.

To override any of that, or to set the order, edit `src/photos/photos.json`. It's keyed by file name; the order of keys is the order on the page:

```json
{
  "my-photo.jpg": { "title": "Last light", "place": "Somewhere quiet", "alt": "What the photo shows" }
}
```

Add `"hidden": true` to keep a file out without deleting it.

The ten `01-…` to `10-…` images are painted placeholders (generated by `scripts/make-placeholder-photos.ts`). Delete them, and their entries in `photos.json`, once your own photos are in.

### Films: Letterboxd

The film diary comes from your public Letterboxd RSS feed (`letterboxd` in `site.config.ts`). It covers your latest 50 diary entries and your lists. `npm run films` refreshes it, and every build does too. If the feed can't be reached, the last saved copy in `src/data/letterboxd.json` is used, so builds never fail because of it.

### Up next: booked shows

Tickets you've booked show above the diary as "Up next", with a countdown, and each drops off by itself once the show is over. BookMyShow has no public API (and bookings sit behind your login), so when you book, you run a workflow. Nothing is committed: the shows are kept in a repository variable (`UP_NEXT_SHOWS`, under Settings → Secrets and variables → Actions → Variables) that each build reads.

**Actions → Add a show → Run workflow** (works from the GitHub mobile app too), and fill in the film (its title, or better, its Letterboxd link; a `boxd.it` link from the app's Share button works too), the date (`2026-12-18`, `18/12` or `18 Dec`), and optionally the time (24-hour, like `20:50`), cinema and format. Then:

- the run checks what you typed (a date it can't read, or one that's passed, fails the run and says why), saves the show, and redeploys the site; the ticket is live a couple of minutes later
- the run's summary shows the film it found on Letterboxd, and every show booked so far
- **Actions → Remove a show** cancels one: part of the film's title, plus the date if you have two shows of one film. If nothing matches, the run fails and its summary lists what's booked
- a show drops off the site the morning after it, and is cleared from the variable the next time you add or remove one

**One-time setup.** The built-in workflow token can't write repository variables, so make a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new) limited to this repository with **Variables: Read and write**, and save it under Settings → Secrets and variables → Actions → Secrets as `UP_NEXT_TOKEN`. The workflows must be on `main` to show up in the Actions tab.

On the night, the ticket follows the show, using the film's running time from Letterboxd (150 minutes if it doesn't have one yet). For a 21:00 show of a 120-minute film:

| Time | The ticket says |
|---|---|
| before 21:00 | the countdown: "3 days to go", then "Today" |
| 21:00 to 23:15 | **Rolling**, till 23:15 (the running time plus a 15-minute interval) |
| 23:15 to 00:00 | **Wrapped**, credits rolled |
| from 00:00 | gone (an hour after the running time is up) |

The page keeps this current by itself, minute by minute, without a rebuild. Show times are read as Indian time (`utcOffset` in `site.config.ts`), whatever time zone the visitor is in. A show without a time just says "Today" and leaves at midnight. The interval, the hour and the 150-minute guess are at the top of `src/lib/up-next.ts`.

Good to know:

- Each film's poster, title and link are fetched from Letterboxd once and saved in `src/data/up-next.json`. If the title leads to no page, or the wrong film, the run's summary says so: remove the show and add it again with the film's Letterboxd link.
- The cinema dropdown (your regular cinemas, named the way BookMyShow does) lives in `.github/workflows/add-show.yml`: edit it there to add or rename one. The ticket shows the name exactly as picked; the list itself isn't shown on the site. "Another cinema" takes any name.
- Only people with write access to the repository can run the workflows, and they do nothing for anyone but the owner. The repository is `upNext` in `site.config.ts`.
- The variable is visible to anyone with access to the repository settings, but the site is public: never put seat numbers or booking IDs in a show.

### Music: Apple Music, via Last.fm

Apple Music has no public "top artists / top songs" for your account (its API only knows recent plays, and Replay has no API), so the charts come from [Last.fm](https://www.last.fm), which counts every play once something sends them there ("scrobbling").

1. **Scrobble Apple Music to Last.fm.** Apple Music can't do it by itself. On iPhone, use a scrobbler app, for example QuietScrob (scrobbles in the background) or an Apple Music player with scrobbling built in, such as Marvis Pro. On a Mac, Last.fm's own desktop Scrobbler picks up the Music app. Charts fill in as you listen; Last.fm can't see plays from before you connect.
2. **Get a Last.fm API key** (free, instant) at <https://www.last.fm/api/account/create>. Only the application name is required.
3. **Tell the site.** Copy `.env.example` to `.env` and paste the key into `LASTFM_API_KEY`, then set `music.lastfm` in `src/site.config.ts` to your Last.fm username.
4. **Run `npm run music`.** The first run looks up cover art, 30-second previews and Apple Music links for each song (Apple allows about 20 searches a minute, so allow ~3 seconds per song) and a photo for each artist. Lookups are saved in `src/data/music.json` and never repeated, so later runs take a second or two. You don't need to commit that file: the deploy workflow keeps its own copy in the Actions cache between runs, so only new songs are looked up.
5. **For the deployed site**, add the same key as a repository secret named `LASTFM_API_KEY` (**Settings → Secrets and variables → Actions**). The scheduled music refresh then updates the charts.

Until `src/data/music.json` has data, the section appears only in `npm run dev`, filled with clearly marked sample data, and production builds leave it (and its dock button) out.

Options in `site.config.ts` → `music`:

- `period`: the chart the page opens on (`'1month'`, `'12month'` or `'overall'`); visitors can switch.
- `storefront`: the Apple Music country (two letters, e.g. `'in'`) used to find previews and links.
- `hide`: artists or song titles to keep off the page.
- `keepTogether`: artists whose name contains "&" or a comma (e.g. `'Simon & Garfunkel'`). Every other collab credit ("A & B") is split so each artist gets their own place in the line-up, with the plays added up; songs keep their full credit.

Only artist and song names are sent to Apple's and Deezer's public catalog search to find artwork; the API key never leaves the build machine and is never printed.

### Tours: trips, day by day

Each trip is one JSON file in `src/data/tours/` (copy `gokarna-dandeli.json` to start one). The file name doesn't matter; `slug` sets the address. On the trip's page every day is a page of its own: as it scrolls in, the map flies to that day's places and draws its route, and train days run a little train along the line with its clock. The map sits on top on a phone and on the right on a big screen. Without JavaScript or WebGL the days read as a plain list.

- `startDate` is Day 0, in India time. The status ("Leaving in 12 days", "On the road · Day 2", "Back home") keeps itself current.
- `places` are the pins, as `[longitude, latitude]`. `town` is the label on the whole-trip map, where places close together share one (the Gokarna temple shows as "Gokarna"). `label: "left"` puts a label on the pin's left, out to sea for coastal places. `overview` picks which places are labelled on that whole-trip map.
- A day has either `train` (`"out"` or `"back"`) or `road`. A train is drawn through its `stations`; leave the way back's `stations` empty to use the outbound line reversed, and leave `number` and times as `null` until you know them, because they're printed. A road is drawn through `via`: run `npm run tours:roads` to swap the straight lines for real roads (it asks the public OSRM router once per day and saves the result in the file, so commit it).
- `legs` splits a day into camera moves, for places too close to see at one zoom: the map frames each leg's places in turn, drawing the route as it goes.

The map is [MapLibre](https://maplibre.org) with [OpenFreeMap](https://openfreemap.org)'s dark style: no API key, no account and no view limits. It loads only on trip pages, after the page is up. To use another style, change `MAP_STYLE` at the top of `src/scripts/trip.ts`.

Trip pages are public, like the rest of the site, and say when you'll be away.

## Deploy

The included workflow, `.github/workflows/deploy.yml`, publishes to GitHub Pages:

1. Push to GitHub, then go to **Settings → Pages → Build and deployment** and set **Source** to **GitHub Actions**.
2. Add your Last.fm key as the repository secret `LASTFM_API_KEY` (without it the deployed site has no soundtrack, because `src/data/music.json` isn't committed).
3. Every push to `main` deploys. Two small workflows also redeploy on a schedule, so new data appears without a commit:
   - **Refresh films** (`refresh-films.yml`): once a day, at 4:30 AM India time, fetches the Letterboxd diary.
   - **Refresh music** (`refresh-music.yml`): at 4 AM and 4 PM India time, fetches the Last.fm charts.

   Each one only refreshes its own source; the other keeps its last saved copy (kept in the Actions cache). To refresh on demand, open the **Actions** tab, pick **Refresh films** or **Refresh music** and press **Run workflow**. **Deploy to GitHub Pages** has the same button with a tick box for each source. GitHub can start scheduled runs a few minutes late. To change the times, edit the `cron` lines in those two files (they are in UTC, India is UTC+05:30).

The project site path (`/my-portfolio/`) and a custom domain are both handled automatically. Any other static host works too: run `npm run build` and serve `dist/`, setting `SITE_URL` (and `BASE_PATH` if it isn't served from the root).

## Where things live

```
src/
  site.config.ts        your words and links
  photos/               your photos + photos.json captions
  data/letterboxd.json  saved diary (written by `npm run films`)
  data/music.json       saved Last.fm charts + artwork lookups (written by `npm run music`)
  data/music.sample.json  made-up charts for designing in dev
  data/up-next.json     Letterboxd posters for booked shows (written by `npm run up-next`)
  data/tours/           one JSON file per trip
  pages/tours/          the tours list and the day-by-day trip pages
  components/           one component per reel, plus the ticket, dock, icons… (tours/ for the trip pages)
  scripts/              the small client-side scripts (ticket physics, viewfinder, turntable, trip map…)
  lib/                  build-time data: films, music, photos (EXIF), tours, helpers
  styles/global.css     tokens, grain, scene lighting, film-strip titles
scripts/
  sync-letterboxd.ts    RSS → JSON
  sync-music.ts         Last.fm → JSON, with Apple artwork/previews and Deezer photos
  sync-up-next.ts       booked films → Letterboxd posters
  fetch-tour-roads.ts   trip days → driving routes (OSRM)
  make-placeholder-photos.ts
```

Typefaces: Archivo (variable width), Instrument Serif and JetBrains Mono, all self-hosted through Fontsource.
